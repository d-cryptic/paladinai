## 2. CI Pipeline (GitHub Actions)

```yaml
# .github/workflows/service-ci.yml
# Triggered on: pull_request, push to main
# Matrix: each service dir that changed (path filter)

on:
  pull_request:
    paths:
      - "services/${{ matrix.service }}/**"
      - "pkg/**"

jobs:
  # ── PARALLEL PHASE 1 ──────────────────────────────────────
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: golangci/golangci-lint-action@v6       # Go services
        # OR for gateway (Rust):
        # run: cargo clippy -- -D warnings

  test:
    runs-on: ubuntu-latest
    steps:
      - run: go test ./... -race -coverprofile=coverage.out
        # OR: cargo test --all-features

  security:
    runs-on: ubuntu-latest
    steps:
      - run: govulncheck ./...
      - run: gosec -severity medium ./...            # Go
        # OR: cargo audit                            # Rust
      - uses: gitleaks/gitleaks-action@v2

  # ── SEQUENTIAL: depends on lint + test + security ─────────
  build:
    needs: [lint, test, security]
    runs-on: ubuntu-latest
    steps:
      - uses: docker/setup-buildx-action@v3
      - run: |
          docker buildx build \
            --platform linux/amd64,linux/arm64 \
            --tag ghcr.io/paladinai/${{ matrix.service }}:${{ github.sha }} \
            --tag ghcr.io/paladinai/${{ matrix.service }}:${{ github.ref_name }} \
            --cache-from type=gha --cache-to type=gha,mode=max \
            --load .

  # ── PARALLEL PHASE 2: depends on build ────────────────────
  scan:
    needs: [build]
    runs-on: ubuntu-latest
    steps:
      - uses: aquasecurity/trivy-action@master
        with:
          image-ref: ghcr.io/paladinai/${{ matrix.service }}:${{ github.sha }}
          severity: CRITICAL,HIGH
          exit-code: 1                               # fail on CRITICAL/HIGH

  eval:
    needs: [build]
    runs-on: ubuntu-latest
    timeout-minutes: 2
    steps:
      - run: npx braintrust eval --suite smoke --cases 10
        env:
          BRAINTRUST_API_KEY: ${{ secrets.BRAINTRUST_API_KEY }}

  # ── SEQUENTIAL: push only on main ─────────────────────────
  push:
    needs: [scan, eval]
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      - run: docker buildx build --push \
               --platform linux/amd64,linux/arm64 \
               --tag ghcr.io/paladinai/${{ matrix.service }}:${{ github.sha }} \
               --tag ghcr.io/paladinai/${{ matrix.service }}:${{ github.ref_name }} .

  update-chart:
    needs: [push]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          repository: paladinai/helm-charts
          token: ${{ secrets.CHART_WRITE_TOKEN }}
      - run: |
          yq e -i '.services.${{ matrix.service }}.image.tag = "${{ github.sha }}"' \
            paladin-control-plane/values.yaml
          git commit -am "ci: bump ${{ matrix.service }} to ${{ github.sha }}"
          git push
```

**Rust gateway** uses identical structure; replace Go steps with `cargo clippy`, `cargo test`, `cargo audit`.

## 4. GitOps Flow

```
Developer pushes PR
│
├─► CI Phase 1 (parallel): lint + test + security
│
├─► CI Phase 2 (sequential): build → scan + eval (parallel)
│
├─► PR review + merge to main
│
├─► CI push image to ghcr.io
│   ghcr.io/paladinai/{service}:{sha}
│   ghcr.io/paladinai/{service}:main
│
├─► CI updates helm-charts/paladin-control-plane/values.yaml
│   .services.{service}.image.tag = {sha}
│   commit + push to helm-charts repo
│
├─► Flux detects git change (poll interval: 1m)
│   HelmRelease reconcile triggered
│
├─► Flux applies HelmRelease to STAGING cluster
│   namespace: paladin-staging
│
├─► Smoke test Job runs against staging
│   (10 E2E cases, timeout 3m)
│   ├─► FAIL → alert Slack, block promotion
│   └─► PASS → continue
│
├─► Manual promotion gate
│   GitHub Environment: "production"
│   Required approvers: 1 team member
│
└─► Flux applies HelmRelease to PROD clusters
    ├─► us-west-2 (primary)
    └─► eu-west-1 (EU tenants)
        (separate Flux instance per cluster)
```

## 6. Multi-Region Strategy

```yaml
# Region topology
regions:
  primary:
    name: us-west-2
    cloud: AWS / GKE
    services: all
    tenants: default (non-EU)

  eu:
    name: eu-west-1
    cloud: AWS / GKE
    services: full stack (mirrored)
    tenants: EU-flagged only
    data-residency: strict (no cross-region egress)

# Routing
routing:
  provider: Cloudflare
  method: geo-routing
  header: X-Tenant-Region
  rules:
    - match: { region: EU }
      target: eu-west-1 cluster ingress
    - match: { region: "*" }
      target: us-west-2 cluster ingress

# NATS
nats:
  topology: separate clusters per region
  cross-region-replication: disabled
  accounts:
    us-west-2: paladin-system-us
    eu-west-1: paladin-system-eu

# PostgreSQL
postgresql:
  topology: primary per region
  cross-region-sync: none
  failover: manual (RTO=1h)
  backup: S3 per region (us-east-1 for us-west-2, eu-central-1 for eu-west-1)

# Shared across regions
shared:
  - ghcr.io images
  - helm-charts repo
  - gateway TOML (model aliases identical)
  - Crossplane compositions
  - Terraform modules
```

**XRD Sketch**:

```yaml
apiVersion: apiextensions.crossplane.io/v1
kind: CompositeResourceDefinition
metadata:
  name: xsilotenants.paladin.io
spec:
  group: paladin.io
  names:
    kind: XSiloTenant
    plural: xsilotenants
  versions:
    - name: v1alpha1
      served: true
      referenceable: true
      schema:
        openAPIV3Schema:
          type: object
          properties:
            spec:
              type: object
              properties:
                tenantId:    { type: string }
                region:      { type: string, enum: [us-west-2, eu-west-1] }
                tier:        { type: string, enum: [silo, enterprise] }
                pgCluster:   { type: boolean, default: false }
```

**Composition flow**:

```yaml
apiVersion: apiextensions.crossplane.io/v1
kind: Composition
metadata:
  name: silo-tenant
spec:
  compositeTypeRef:
    apiVersion: paladin.io/v1alpha1
    kind: XSiloTenant
  resources:
    - name: namespace
      base:
        apiVersion: kubernetes.crossplane.io/v1alpha1
        kind: Object
        spec:
          forProvider:
            manifest:
              apiVersion: v1
              kind: Namespace
              metadata:
                name: paladin-tenant-PATCH

    - name: nats-account
      base:
        apiVersion: nats.crossplane.io/v1alpha1
        kind: Account
        spec:
          forProvider:
            server: nats://nats.paladin.svc:4222

    - name: qdrant-namespace
      base:
        apiVersion: qdrant.crossplane.io/v1alpha1
        kind: Collection
        spec:
          forProvider:
            collectionPrefix: tenant-PATCH

    - name: valkey-db
      base:
        apiVersion: valkey.crossplane.io/v1alpha1
        kind: LogicalDB
        spec:
          forProvider:
            dbIndex: 0                          # patched per tenant (1-15)

    - name: postgresql-schema
      base:
        apiVersion: sql.crossplane.io/v1alpha1
        kind: Database
        spec:
          forProvider:
            schemaName: tenant_PATCH
            # enterprise: provision separate PG cluster instead

  # Patches apply tenantId → resource names
  patches:
    - fromFieldPath: spec.tenantId
      toFieldPath: metadata.name
```

**Trigger**: webhook from billing service when tenant upgrades → creates `XSiloTenant` CR → Crossplane reconciles all resources.

## 8. Rollout Strategy

```yaml
# Default: all Go services
strategy:
  type: RollingUpdate
  rollingUpdate:
    maxSurge: 25%
    maxUnavailable: 0

# paladin-gateway (Rust) — canary via Linkerd TrafficSplit
canary:
  tool: Linkerd TrafficSplit
  stages:
    - weight: 10%   # 10 min soak, error rate < 0.1%
    - weight: 50%   # 10 min soak
    - weight: 100%  # promote; delete old deployment
  rollback: shift traffic back to stable; delete canary deployment

# paladin-agent-worker — blue/green
blue_green:
  deploy: new version alongside old (different Deployment label)
  drain: wait for NATS consumer lag = 0 on old pods
  cutover: update Service selector to new label
  cleanup: delete old Deployment after 5 min

# Database migrations
migrations:
  runner: init container (before app container starts)
  tool: golang-migrate / flyway
  policy: backward-compatible always (no column drops in same release)
  rollback: additive-only schema changes; feature flag to disable new paths

# Feature flags
feature_flags:
  mechanism: environment variable
  deployment: Helm values override
  no-external-service: true
  example:
    - FEATURE_HYPOTHESIS_AGENT_V2=true
    - FEATURE_STREAMING_ENABLED=false
```

## 9. Disaster Recovery

```yaml
rto_rpo:
  postgresql:
    backup: daily snapshot to S3 (per-region bucket)
    pitr: enabled (WAL archive every 5 min)
    rto: 1h
    rpo: 5min
    restore-cmd: |
      aws rds restore-db-instance-to-point-in-time \
        --source-db-instance-identifier paladin-prod \
        --target-db-instance-identifier paladin-restore \
        --restore-time 2026-05-10T12:00:00Z

  qdrant:
    snapshot: every 6h to S3
    rto: 2h
    rpo: 6h
    restore-cmd: |
      qdrant-restore --snapshot s3://paladin-backups/qdrant/latest.snapshot \
        --collection-name paladin

  nats:
    storage: JetStream file storage
    replication: 3 nodes (R=3), survives 1 node loss with zero data loss
    rto: 15min (restart surviving nodes)
    rpo: 0 (replicated)

  valkey:
    persistence: AOF fsync every 1 second
    rto: 15min (cache rebuilt from source of truth on miss)
    rpo: 1s

runbooks:
  dr: docs/runbooks/disaster-recovery.md
  pg-restore: docs/runbooks/pg-restore.md
  nats-recovery: docs/runbooks/nats-recovery.md
```

## 10. Release Process

```yaml
versioning:
  scheme: semver (MAJOR.MINOR.PATCH)
  tags: on main branch → trigger release pipeline
  helm-chart-version: matches app version

changelog:
  tool: git-cliff / conventional-changelog
  source: conventional commits (feat, fix, perf, breaking)
  output: CHANGELOG.md + GitHub Release notes

release-pipeline:
  trigger: git tag v*.*.*
  steps:
    - eval: full braintrust suite (all cases, not just smoke)
    - security: trivy + gosec / cargo audit (zero CRITICAL)
    - staging-smoke: deploy to staging, run E2E, assert pass
    - team-sign-off: GitHub Environment approval (2 approvers for MAJOR)
    - publish: push Helm chart to OCI (ghcr.io/paladinai/charts/)
    - release: create GitHub Release with changelog

hotfix-path:
  branch-from: release tag (git checkout -b hotfix/v1.2.1 v1.2.0)
  fix: minimal targeted change
  test: unit + smoke only (fast-track)
  tag: patch version (v1.2.1)
  merge-back: cherry-pick to main
  ci: same pipeline, no manual gate skipped

release-checklist:
  - [ ] eval full suite pass (braintrust)
  - [ ] security scan pass (zero CRITICAL/HIGH)
  - [ ] staging smoke pass (E2E)
  - [ ] CHANGELOG.md updated
  - [ ] Helm chart version bumped
  - [ ] team sign-off (GitHub Environment approval)
  - [ ] runbook updated if ops change
```
