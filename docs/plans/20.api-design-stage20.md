# PaladinAI v2 — Stage 20: External API Design

**Base URL:** `https://api.paladinai.io/v2`  
**Auth:** `Authorization: Bearer <jwt>` or `X-API-Key: <key>`  
**Format:** JSON, ISO 8601 timestamps, UUID v7 IDs  
**Rate limits:** 600 req/min authenticated · 30 req/min write endpoints  
**Error shape:** `{"error": {"code": "...", "message": "...", "details": [...]}}`

---

## 2. Incidents API

### GET /incidents

**Query params:**

| Param | Type | Example |
|-------|------|---------|
| `severity` | enum | `p1,p2` |
| `status` | enum | `open,resolved` |
| `service` | string | `payments-api` |
| `from` | ISO 8601 | `2026-05-01` |
| `to` | ISO 8601 | `2026-05-10` |
| `cursor` | string | opaque cursor |
| `limit` | int | `20` (max 100) |
| `sort` | string | `created_at:desc` |

**Response `200`:**
```json
{
  "data": [{ "id": "...", "severity": "p1", "status": "open", "title": "...", "created_at": "..." }],
  "meta": { "cursor": "abc123", "has_more": true, "total": 142 }
}
```

  "signals": [
    { "id": "...", "source": "datadog", "type": "metric_alert", "severity": "critical", "received_at": "..." }

### POST /incidents/{id}/signals

**Request:**
```json
{ "source": "custom", "type": "log_pattern", "payload": { "pattern": "ENOMEM", "count": 842 } }
```

**Response `201`:** `{ "signal_id": "..." }`

### POST /incidents/{id}/approve / reject

**Request:**
```json
{ "action_id": "...", "reason": "Confirmed safe to proceed" }
```

**Response `200`:** `{ "action_id": "...", "status": "approved" }`

### POST /incidents/{id}/postmortem

**Request:**
```json
{
  "summary": "Memory leak in v2.4.1 — deployment gap in load testing.",
  "timeline": "...",
  "contributing_factors": ["Missing OOM alerting", "No staging load test"],
  "action_items": [{ "owner": "alice", "task": "Add OOM alert", "due": "2026-05-17" }]
}
```

**Response `200`:** `{ "postmortem_id": "...", "memory_consolidation_queued": true }`

### GET /incidents/{id}/timeline

Returns SSE stream (`Content-Type: text/event-stream`).

```
event: signal_received
data: {"signal_id": "...", "source": "pagerduty", "ts": "2026-05-10T13:01:00Z"}

event: rca_ready
data: {"confidence": 0.91, "ts": "2026-05-10T13:08:00Z"}
```

## 3. Alerts API

### POST /alerts/ingest

Accepts either a normalized `AlertEnvelope` or a raw payload with a source hint.

**Request — normalized:**
```json
{
  "source": "custom",
  "severity": "critical",
  "title": "DB connection pool exhausted",
  "service": "user-api",
  "labels": { "region": "us-east-1", "env": "production" },
  "payload": { "pool_size": 100, "active": 100, "waiting": 47 },
  "timestamp": "2026-05-10T14:00:00Z"
}
```

**Request — raw with hint:**
```json
{ "source_type": "cloudwatch", "raw": { ...cloudwatch alarm object... } }
```

**Response `201`:**
```json
{
  "alert_id": "01928a1b-...",
  "incident_id": "01927f3a-...",
  "action": "correlated"
}
```

`action` values: `correlated` (added to existing), `new_incident` (triggered new), `suppressed` (below threshold).

### GET /alerts

**Query params:** `source`, `severity`, `incident_id`, `from`, `to`, `cursor`, `limit`

**Response `200`:** Standard paginated list with alert summary objects.

### GET /alerts/{id}

**Response `200`:**
```json
{
  "id": "01928a1b-...",
  "source": "datadog",
  "severity": "critical",
  "title": "...",
  "received_at": "...",
  "normalized": { "service": "payments-api", "labels": {} },
  "incident_id": "01927f3a-...",
  "correlation_reason": "Same service + overlapping time window"
}
```

## 6. Webhooks — Outbound

PaladinAI posts events to customer-registered URLs.

### Event Types

| Event | Trigger |
|-------|---------|
| `incident.created` | New incident opened |
| `incident.classified` | Severity + intent determined |
| `incident.rca_ready` | RCA report generated |
| `incident.action_proposed` | Runbook step needs approval |
| `incident.resolved` | Incident closed |
| `alert.correlated` | Alert grouped into existing incident |

### Payload Envelope

```json
{
  "event": "<event_type>",
  "timestamp": "<ISO 8601>",
  "tenant_id": "<tenant>",
  "delivery_id": "<uuid-v7>",
  "data": { ... }
}
```

### Example: incident.rca_ready

```json
{
  "event": "incident.rca_ready",
  "timestamp": "2026-05-10T14:32:00Z",
  "tenant_id": "acme-corp",
  "delivery_id": "01929c4d-...",
  "data": {
    "incident_id": "01927f3a-...",
    "title": "Elevated error rate on payments-api",
    "severity": "p1",
    "status": "investigating",
    "root_cause": "Memory leak in payments-api v2.4.1 causing OOM restarts",
    "confidence": 0.91,
    "blast_radius": ["payments-api", "checkout-svc", "auth-svc"],
    "evidence": ["spike in OOMKilled events at 13:02Z", "deploy at 12:55Z"],
    "proposed_actions": [
      { "step": 1, "description": "Roll back payments-api to v2.4.0", "risk": "low", "status": "pending_approval" }
    ],
    "rca_url": "https://app.paladinai.io/incidents/01927f3a-..."
  }
}
```

### Webhook Security

- **Signature:** HMAC-SHA256 of the raw request body, sent in `X-Paladin-Signature: sha256=<hex>`.
- **Verification:** Compute `HMAC-SHA256(secret, raw_body)` and compare to header value (constant-time compare).
- **Retry:** 3 attempts with exponential backoff (5s, 25s, 125s). Consider 2xx a success.
- **Dead letter:** After 3 failures, payload is forwarded to `dlq_url` if configured on the webhook.
- **Timeout:** 10 seconds per attempt.

### Register Webhook

**POST /webhooks**

```json
{
  "url": "https://hooks.acme.com/paladin",
  "events": ["incident.rca_ready", "incident.action_proposed"],
  "secret": "whs_...",
  "dlq_url": "https://hooks.acme.com/paladin/dlq"
}
```

**Response `201`:** `{ "webhook_id": "...", "status": "active" }`

## 7. Pagination & Filtering

**Cursor-based pagination** on all list endpoints.

| Param | Default | Max | Notes |
|-------|---------|-----|-------|
| `cursor` | — | — | Opaque string from previous response |
| `limit` | `20` | `100` | Items per page |

**Response meta:**
```json
{ "cursor": "eyJpZCI6Ii4uLiJ9", "has_more": true, "total": 312 }
```

**Common filter params:**

| Param | Type | Example |
|-------|------|---------|
| `severity` | comma-list | `p1,p2` |
| `status` | comma-list | `open,resolved` |
| `service` | string | `payments-api` |
| `from` | ISO 8601 date | `2026-05-01` |
| `to` | ISO 8601 date | `2026-05-10` |
| `sort` | `field:asc\|desc` | `created_at:desc` |

**Multiple values:** comma-separated (`severity=p1,p2`) or repeated params (`severity=p1&severity=p2`).

## 8. API Versioning & Deprecation

| Policy | Rule |
|--------|------|
| Versioning scheme | URL path: `/v2/`, `/v3/` |
| Backward-compatible additions | New optional fields, new endpoints — no version bump |
| Breaking changes | New major version required |
| Support window | Previous version supported for 6 months post-deprecation announcement |
| Deprecation header | `Deprecation: true` + `Sunset: 2027-01-01` on deprecated endpoints |
| Migration guide | Published at `https://docs.paladinai.io/api/migration/v2-v3` |
| Sunset notification | Email + in-API header 90 days before sunset date |
