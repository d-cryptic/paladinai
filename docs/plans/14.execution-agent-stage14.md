## Common Conventions

| Symbol | Meaning |
|--------|---------|
| `→`    | function call or direct handoff |
| `⟹`   | async NATS publish |
| `▶`    | Hatchet step boundary |
| `[OPA]`| OPA policy check |
| `[VLT]`| Vault secret access |
| `[CH]` | ClickHouse audit write |

**Default stance:** CONSERVATIVE. Class B requires human approval unless the tenant
explicitly opts in per action type in `paladin.yaml`.

## 1. Three Execution Classes

### Classification Table

| Class | Name           | Default Policy      | Tenant Override | Examples |
|-------|----------------|---------------------|-----------------|---------|
| A     | Read-only      | Always auto-execute | N/A (no change needed) | `kubectl get/describe/logs`, Prometheus query, Loki tail, PagerDuty list incidents |
| B     | Reversible write | Require approval   | Opt-in per action in `paladin.yaml` | `kubectl rollout restart`, PagerDuty ack/resolve, Slack post, scale UP |
| C     | Destructive     | Always approval     | No override ever | `kubectl delete`, scale DOWN/terminate, DB mutations, secret rotation |

### Class A — Read-Only (auto-execute)

All reads are always safe to run without human gate.

```
mcp-k8s:   get, describe, logs, top, events
mcp-prom:  instant_query, range_query, label_values
mcp-loki:  query_range, tail, labels
mcp-pagerduty: list_incidents, get_incident, list_services
mcp-github: get_pr, list_commits, diff
```

### Class B — Reversible Writes (approval by default)

Writes that can be undone. Human gate unless tenant opts in.

```
mcp-k8s:        rollout_restart, rollout_pause, rollout_resume,
                 scale_up (replicas++)
mcp-pagerduty:  acknowledge, resolve, add_note, escalate_policy
mcp-slack:      post_message, update_message
mcp-github:     create_pr, add_comment
```

### Class C — Destructive / Irreversible (always approval, no override)

Cannot be safely undone in real-time, or risk data loss / outage.

```
mcp-k8s:        delete (pod/deployment/ns), scale_down (replicas--),
                 drain_node, cordon
mcp-rds:        run_query (DML), snapshot, restore, failover
mcp-vault:      rotate_secret, revoke_lease
mcp-pagerduty:  delete_incident, reassign_escalation_policy
```

## 2. Policy Engine (OPA)

### paladin.yaml — Execution Policy Config

```yaml
apiVersion: paladin.io/v2
kind: RunbookPolicy
metadata:
  tenant: acme-corp
spec:
  execution:
    # Class A is always auto — no config needed.

    auto_execute:
      - class: B
        conditions:
          severity: [p1]                        # P1 incidents only
          actions:
            - rollout_restart
            - pagerduty_ack
        # All other Class B actions fall through to require_approval.

    require_approval:
      - class: C                                # always, no override path
      - class: B                                # default for unmatched B actions

    approval:
      timeout_minutes: 30                       # Hatchet signal wait timeout
      escalate_on_timeout: true                 # page on-call if nobody approves
      notify:
        - channel: slack
          target: "#incidents"
        - channel: pagerduty
          policy: default-escalation
```

### OPA Rego Policy Sketch

```rego
package paladin.execution

import future.keywords.if
import future.keywords.in

default allow = false
default requires_approval = false

# Class A: always allow, never needs approval
allow if {
    input.action_class == "A"
}

# Class B: auto-execute only when tenant has opted in AND conditions match
allow if {
    input.action_class == "B"
    not requires_approval
}

requires_approval if {
    input.action_class == "B"
    not b_auto_eligible
}

b_auto_eligible if {
    auto := data.tenants[input.tenant_id].execution.auto_execute[_]
    auto.class == "B"
    input.severity in auto.conditions.severity
    input.action_name in auto.conditions.actions
}

# Class C: always requires approval, no allow path
requires_approval if {
    input.action_class == "C"
}

# OPA never allows C without approval token
allow if {
    input.action_class == "C"
    input.approval_token != ""
    valid_approval_token(input.approval_token)
}

valid_approval_token(token) if {
    # JWT signed by paladin-approval-service, verified via JWKS
    io.jwt.verify_rs256(token, data.jwks)
    claims := io.jwt.decode(token)
    claims[1].action_id == input.action_id
    claims[1].exp > time.now_ns() / 1000000000
}
```

OPA input shape:

```json
{
  "tenant_id": "acme-corp",
  "action_id": "01HZ...",
  "action_name": "rollout_restart",
  "action_class": "B",
  "severity": "p1",
  "incident_id": "INC-9821",
  "user_roles": ["sre", "on-call"],
  "approval_token": ""
}
```

OPA runs as a sidecar (`opa run --server`) on the `paladin-agent` pod.
Policy bundles are fetched from S3 on startup and refreshed every 60s.

## 3. Dangerous Command Detection Layer

Before ANY Class B or C action executes, a fast LLM gate inspects it.

```
                    Action proposed
                         │
              ┌──────────▼──────────┐
              │  dangerous_check()  │  <── Tier A LLM call, <500ms
              │  action + params    │      (Haiku or equivalent)
              │  + context summary  │
              └──────────┬──────────┘
                         │
           ┌─────────────┴─────────────┐
           │ flagged?                  │ clean
           ▼                           ▼
    Escalate to Class C          Proceed with
    (override tenant policy)     original class
           │
           ▼
    Log: dangerous_check_flags[]
    Continue to approval gate
```

**Dangerous pattern list (stored in PG `dangerous_patterns` table, loaded at startup):**

| Pattern ID | Description | Trigger keywords / regex |
|------------|-------------|--------------------------|
| DP-01 | Mass deletion | `delete.*--all`, `delete.*-n.*production` |
| DP-02 | Cross-namespace write | action targets namespace != incident namespace |
| DP-03 | Production data mutation | SQL DML on `production` schema |
| DP-04 | Credential access | secret rotation, Vault lease on non-incident service |
| DP-05 | Cascading scale-down | scale < 1 on multi-replica stateful set |
| DP-06 | Drain with PDB violation | node drain would violate PodDisruptionBudget |

Pattern list is versioned (`version`, `updated_at`, `updated_by`) and reloaded
without restart via NATS `paladin.internal.patterns.reload` signal.

**LLM prompt template (abbreviated):**

```
You are a safety reviewer for infrastructure actions.
Action: {{action_name}}
Params: {{params_redacted}}
Context: {{incident_summary}} | Severity: {{severity}} | Namespace: {{namespace}}

Dangerous patterns to check:
{{pattern_list}}

Respond JSON: {"flagged": bool, "flags": ["DP-01", ...], "reason": "..."}
```

## 4. Execution Flow (Hatchet Workflow)

```
RunbookAgent proposes ExecuteAction{name, params, class, incident_id}
         │
         ▶ Step: classify_action
         │    classify_action_step(action_name) → class A/B/C
         │    [OPA] policy_check(tenant, action, class) → allow | require_approval
         │
         ├─ Class A → ▶ Step: execute_mcp (immediate)
         │
         └─ Class B / C
                │
                ▶ Step: dangerous_command_check
                │    fast LLM call → {flagged, flags}
                │    if flagged → override class to C
                │    write DangerousCheckResult to PG
                │
                ├─ [OPA] re-evaluate with final class
                │
                ├─ if allow (Class B auto) → ▶ Step: execute_mcp
                │
                └─ if requires_approval
                         │
                         ▶ Step: emit_approval_request
                         │    ⟹ NATS: paladin.approval.{tenant}.required
                         │    → paladin-ws broadcasts to browser session
                         │    Write PendingApproval{action_id, expires_at} to PG
                         │
                         ▶ Step: wait_for_approval   [Hatchet signal wait]
                         │    timeout: paladin.yaml approval.timeout_minutes
                         │
                         ├─ signal: approved
                         │    verify approval_token (OPA JWT check)
                         │    ▶ Step: execute_mcp
                         │
                         ├─ signal: rejected
                         │    ▶ Step: log_rejection → [CH] audit
                         │    Hatchet workflow → ABORTED
                         │
                         └─ timeout
                                  ▶ Step: handle_timeout
                                  │    if escalate_on_timeout: page on-call via PagerDuty
                                  │    [CH] audit (timeout)
                                  Hatchet workflow → ABORTED

After execute_mcp:
         ▶ Step: run_post_hooks (async, best-effort)
         ▶ Step: verify_execution
         │    if verify fails → propose_rollback (not auto-execute)
         ▶ Step: write_audit [CH]
```

**Hatchet step idempotency:** `ExternalID = action_id:step_name`
All steps are retryable with exponential backoff except `wait_for_approval`
(human signal — not retried).

## 5. Audit Log Schema (ClickHouse)

Table: `execution_audit` — immutable, append-only, no deletes, no updates.

```sql
CREATE TABLE execution_audit
(
    action_id           UUID,           -- UUIDv7, sortable by time
    tenant_id           String,
    incident_id         String,
    action_name         LowCardinality(String),
    action_class        Enum8('A'=1, 'B'=2, 'C'=3),
    mcp_server          LowCardinality(String),
    params_hash         String,         -- SHA-256 of raw params, never raw params
    policy_decision     Enum8('auto'=1, 'approved'=2, 'rejected'=3, 'timeout'=4),
    approver_id         Nullable(String),
    dangerous_flagged   Bool,
    dangerous_flags     Array(String),  -- ['DP-01', 'DP-03']
    dangerous_reason    Nullable(String),
    execution_result    Enum8('success'=1, 'failure'=2, 'skipped'=3),
    error_message       Nullable(String),
    rollback_proposed   Bool,
    rollback_action_id  Nullable(UUID),
    executed_at         DateTime64(3, 'UTC'),
    duration_ms         UInt32,
    hatchet_run_id      String
)
ENGINE = ReplicatedMergeTree('/clickhouse/tables/{shard}/execution_audit', '{replica}')
ORDER BY (tenant_id, executed_at, action_id)
PARTITION BY toYYYYMM(executed_at)
TTL executed_at + INTERVAL 2 YEAR;
```

**Sensitive data policy:** raw action params are never written. Only `SHA-256(params_json)`
is stored. Full params are written to encrypted PG table `execution_params` with 90-day TTL,
accessible only by auditors with Vault-issued credentials.

## 6. Agentic Hooks System

### paladin.yaml — Hook Config

```yaml
spec:
  hooks:
    pre_execute:
      - action: kubectl_rollout_restart
        hooks:
          - type: notify_slack
            config:
              channel: "#deployments"
              message: "Paladin is restarting {{params.deployment}} in {{params.namespace}}"
          - type: check_slo_budget
            config:
              threshold_percent: 10     # abort if error budget < 10%
              slo_name: "{{params.service}}-availability"

      - action: kubectl_scale_up
        hooks:
          - type: notify_pagerduty
            config:
              note: "Auto-scaling {{params.deployment}} to {{params.replicas}} replicas"

    post_execute:
      - action: kubectl_rollout_restart
        hooks:
          - type: verify_pod_health
            config:
              timeout_seconds: 120
              min_ready_percent: 90
          - type: update_incident_log
          - type: run_smoke_test
            config:
              test_suite: "{{params.service}}-smoke"
              timeout_seconds: 60

      - action: pagerduty_acknowledge
        hooks:
          - type: update_incident_log
```

### Hook Types Reference

| Hook Type           | Phase | Sync? | Can Abort? | Description |
|---------------------|-------|-------|------------|-------------|
| `notify_slack`      | pre   | async | no         | Post message to Slack channel |
| `notify_pagerduty`  | pre   | async | no         | Add note to PagerDuty incident |
| `check_slo_budget`  | pre   | sync  | yes        | Query Prometheus SLO budget; abort if below threshold |
| `verify_pod_health` | post  | sync  | no*        | Poll k8s for pod ready %; trigger rollback if fails |
| `run_smoke_test`    | post  | sync  | no*        | Run test suite; trigger rollback proposal if fails |
| `update_incident_log` | post | async | no        | Append execution summary to incident timeline |

*post-hooks cannot abort the action (already executed) but can trigger rollback proposal.

### Hook Execution Model

```
Pre-hooks (synchronous chain):
    hook_1 → hook_2 → hook_3 → [execute action]
         abort signal from any hook cancels chain → action not executed
         timeout per hook: 10s (configurable), chain timeout: 30s

Post-hooks (async, best-effort):
    [action executed] → fan-out goroutines
         each hook runs independently
         failures are logged but do not affect audit result
         verify_pod_health / run_smoke_test: if failed → propose_rollback()
```

Hook implementations are Go functions registered in `hooks/registry.go`:

```go
// hooks/registry.go
type HookFn func(ctx context.Context, in HookInput) (HookResult, error)

type HookInput struct {
    ActionName  string
    ActionClass string
    Params      map[string]any   // resolved template values
    IncidentID  string
    TenantID    string
    Config      map[string]any
}

type HookResult struct {
    Abort   bool
    AbortReason string
    Metadata    map[string]any
}

var Registry = map[string]HookFn{
    "notify_slack":       hooks.NotifySlack,
    "notify_pagerduty":   hooks.NotifyPagerDuty,
    "check_slo_budget":   hooks.CheckSLOBudget,
    "verify_pod_health":  hooks.VerifyPodHealth,
    "run_smoke_test":     hooks.RunSmokeTest,
    "update_incident_log": hooks.UpdateIncidentLog,
}
```

## 7. Human Approval UX (WebSocket)

### Approval Flow

```
paladin-agent (Hatchet step: emit_approval_request)
     │
     ⟹ NATS: paladin.approval.{tenant_id}.required
     │
paladin-ws (WebSocket gateway)
     │  fan-out to all authenticated browser sessions for tenant
     │
     ▼
Browser receives approval_required event
     │
     ├─ Shows approval modal with full context
     ├─ Countdown timer (timeout_minutes)
     └─ User clicks Approve / Reject / Modify
          │
          ▼
     Browser sends approval_response event → paladin-ws
          │
          ▼
     paladin-ws validates JWT session, emits Hatchet signal
          │
          ▼
     paladin-agent resumes wait_for_approval step
```

### WebSocket Message Schema

**approval_required** (server → browser):

```json
{
  "type": "approval_required",
  "action_id": "01HZ4X...",

  "tenant_id": "acme-corp",

    "name": "kubectl_rollout_restart",

    "blast_radius": {

  "expires_at": "2026-05-10T14:30:00Z",
  "timeout_seconds": 1800,
  "requested_by": "paladin-runbook-agent"
}
```

**approval_response** (browser → server):

```json
{
  "type": "approval_response",
  "action_id": "01HZ4X...",
  "decision": "approved",
  "approver_id": "user:jane@acme.com",
  "modified_params": null,
```

`decision` values: `"approved"` | `"rejected"` | `"modified"` (params editor)

`paladin-ws` calls the push notification service on `approval_required` for P1.
Push payload is a deep link that opens the approval modal in the mobile web app.

## 8. Rollback Design

Every Class B action has a defined inverse. Rollback is PROPOSED (not auto-executed)
if `verify_pod_health` or `run_smoke_test` post-hook fails.

### Rollback Map

| Original Action         | Rollback Action              | Class | Notes |
|-------------------------|------------------------------|-------|-------|
| `rollout_restart`       | `rollout_undo`               | B     | Reverts to previous RS |
| `scale_up` (N→M)        | `scale` (M→N original)       | B     | Original replica count stored in action params |
| `pagerduty_ack`         | `pagerduty_unacknowledge`    | B     | Re-opens incident |
| `pagerduty_resolve`     | `pagerduty_unresolve`        | C     | PD API: reopen |
| `rollout_pause`         | `rollout_resume`             | B     | |
| `scale_down`            | `scale` (back to M)          | C     | Class C original → rollback also C |

Rollback proposal is sent as a new `approval_required` WebSocket event with
`proposed_action.rationale` set to the failure reason and `blast_radius` computed
for the rollback action.

**Rollback itself requires approval** — same class as the original action.
Class C original → rollback is also Class C (no override).

## 9. MCP Server Action Safety

Each MCP server enforces action safety independently as a defense-in-depth layer.
The `paladin-agent` MUST include the following headers on every MCP call:

```
X-Paladin-Tenant-ID:    acme-corp
X-Paladin-Action-Class: B
X-Paladin-Policy-Token: <short-lived JWT>
X-Paladin-Action-ID:    01HZ4X...
X-Paladin-Incident-ID:  INC-9821
```

### Policy Token (JWT)

Signed by OPA (RSA-256, 5-minute TTL) after a successful policy check.
Proves to the MCP server that the OPA evaluation ran and approved this action.

```json
{
  "iss": "paladin-opa",
  "sub": "acme-corp",
  "action_id": "01HZ4X...",
  "action_name": "kubectl_rollout_restart",
  "action_class": "B",
  "approval_token": "<if human approved, nested JWT>",
  "exp": 1715350000,
  "iat": 1715349700
}
```

### mcp-k8s Safety Rules

```
Read commands  (Class A): kubectl get, describe, logs, top, events
  → No policy token check required (but tenant_id still required)
  → Namespace-scoped to incident namespace by default

Write commands (Class B/C): kubectl rollout, scale, delete, drain
  → REQUIRE X-Paladin-Action-Class header
  → REQUIRE valid X-Paladin-Policy-Token (5-min TTL JWT)
  → Namespace whitelist enforced: only namespaces listed in tenant's
    paladin.yaml namespace_allow_list
  → If X-Paladin-Action-Class: C → require approval_token field in JWT
```

No MCP server will execute a write command without a valid policy token.
Policy token validation is done locally (embedded public key) — no network call.

### MCP Server Safety Implementation (Go sketch)

```go
// mcp-k8s/middleware/policy.go

func PolicyTokenMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        actionClass := r.Header.Get("X-Paladin-Action-Class")
        if actionClass == "" || actionClass == "A" {
            next.ServeHTTP(w, r)
            return
        }

        token := r.Header.Get("X-Paladin-Policy-Token")
        claims, err := verifyPolicyToken(token)   // local RSA-256 verify
        if err != nil {
            http.Error(w, "invalid policy token", http.StatusForbidden)
            return
        }

        if actionClass == "C" && claims.ApprovalToken == "" {
            http.Error(w, "class C requires approval token", http.StatusForbidden)
            return
        }

        ctx := context.WithValue(r.Context(), policyClaimsKey, claims)
        next.ServeHTTP(w, r.WithContext(ctx))
    })
}
```

## Key Design Invariants

1. **OPA is the single source of truth** for execution policy. No code path bypasses it.
2. **Dangerous command detection runs before every B/C action**, regardless of tenant opt-in.
3. **Class C has no auto-execute path**, even for P0 incidents. A human must approve.
4. **MCP servers verify policy tokens locally** — no circular dependency on paladin-agent during execution.
5. **Audit logs are immutable** (append-only ClickHouse). Raw params are never stored in CH.
6. **Rollback is proposed, not automatic** — engineers retain control over recovery actions.
7. **All pre-hooks that can abort run synchronously** before execution begins.
8. **Hatchet signal timeout escalates** — if approval lapses, on-call is paged and action aborted.
