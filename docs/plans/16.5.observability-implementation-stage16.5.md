# Stage 16.5 Observability Implementation

**Status:** in progress  
**Scope:** local ClickStack/HyperDX wiring, OTel metrics/traces/log correlation, LLM trace export path

## Runtime Topology

```
paladin-* services
  OTLP gRPC :4317
      |
      v
paladin-otel-collector
  |-- traces/logs/metrics --> ClickStack all-in-one (HyperDX + ClickHouse)
  |-- metrics -------------> Prometheus :8889
  |-- traces/logs ---------> debug exporter for local inspection
```

ClickStack is optional in local development and is started with:

```bash
make up-observability
```

The HyperDX UI is exposed at `http://localhost:8088`. Direct OTLP ports are
also exposed on `14317` and `14318` for collector smoke tests without colliding
with the repo's primary collector on `4317` and `4318`.

## Implemented

- `internal/telemetry` now initializes both traces and metrics over OTLP gRPC.
- Service logs can include `trace_id` and `span_id` through `telemetry.TraceFields`.
- `paladin-agent` initializes telemetry on startup.
- Agent worker spans:
  - `paladin.agent.handle_message`
  - `paladin.agent.process`
  - `paladin.agent.publish_result`
- Agent worker metrics:
  - `paladin_incidents_triaged_total`
  - `paladin_agent_failures_total`
  - `paladin_agent_duration_seconds`
  - `paladin_agent_publish_duration_seconds`
- OpenRouter model wrapper emits one GenAI span per call:
  - `paladin.llm.generate`
  - `paladin.llm.stream`
- LLM metrics:
  - `paladin_llm_calls_total`
  - `paladin_llm_failures_total`
  - `paladin_llm_duration_seconds`
  - `paladin_llm_tokens_total`

## LLM Observability

Langfuse supports OpenTelemetry trace ingestion over OTLP/HTTP at
`/api/public/otel`; it does not currently support OTLP/gRPC ingestion. The repo
therefore emits standard GenAI span attributes from Go and keeps Langfuse export
as a collector route rather than a direct application dependency.

The example collector config is:

```text
infra/otel/collector-langfuse.example.yaml
```

Production deployments should route only LLM-relevant traces to Langfuse and
keep all service telemetry in ClickStack/ClickHouse. The agent emits
`gen_ai.*`, `langfuse.observation.type`, and `paladin.llm_tier` attributes so
Langfuse can identify generations while ClickStack still receives the complete
trace.

## Correlation Rules

- Every incident span should carry `paladin.tenant_id`, `paladin.incident_id`,
  `paladin.severity`, and `paladin.fingerprint` when available.
- Every log inside an active span should include `trace_id` and `span_id`.
- Every LLM span should carry:
  - `gen_ai.system`
  - `gen_ai.operation.name`
  - `gen_ai.request.model`
  - `gen_ai.response.model`
  - `paladin.llm_tier`
- Token counters should use `token_type=input|output|total`.
