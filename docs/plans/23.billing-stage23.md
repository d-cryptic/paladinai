# Stage 23 — Billing & Metering

## 1. Billing Model

| Tier   | Monthly Base | Included Incidents | Included Tokens | Incident Overage    | Token Overage         |
|--------|--------------|--------------------|-----------------|---------------------|-----------------------|
| Pool   | $0           | 100                | 500K            | $0.010 / incident   | $0.002 / 1K tokens   |
| Bridge | $299         | 1,000              | 5M              | $0.008 / incident   | $0.0015 / 1K tokens  |
| Silo   | Custom       | Unlimited          | Unlimited       | N/A (infra cost)    | N/A                   |

### Add-ons

| Add-on                        | Price              | Notes                                   |
|-------------------------------|--------------------|-----------------------------------------|
| Extra integration slot        | $49 / integration  | Beyond base allotment per tier          |
| Dedicated vLLM inference      | $0.60 / GPU-hour   | Billed by actual compute time           |
| EU data residency             | +$50 / month       | ClickHouse + PG replicated in eu-west-1 |

### Overage Formula

```
incident_overage = max(0, incidents_used - incidents_included) × overage_rate
token_overage    = max(0, tokens_used - tokens_included) / 1000 × token_rate
monthly_total    = base_fee + incident_overage + token_overage + sum(add_ons)
```

## 2. Metering Events — ClickHouse Schema

```sql
CREATE TABLE billing_events
(
    event_id        UUID          DEFAULT generateUUIDv4(),
    tenant_id       String,
    event_type      Enum8(
                        'incident_triaged'     = 1,
                        'llm_call'             = 2,
                        'tool_call'            = 3,
                        'runbook_step'         = 4,
                        'memory_consolidation' = 5
                    ),
    quantity        Float64,          -- tokens, calls, incidents
    unit            LowCardinality(String),  -- 'tokens' | 'calls' | 'incidents'
    cost_usd        Decimal(10, 6),
    model           LowCardinality(String),  -- for llm_call events
    provider        LowCardinality(String),  -- 'anthropic' | 'openai' | 'local'
    agent_type      LowCardinality(String),
    incident_id     String,
    timestamp       DateTime64(3)
)
ENGINE = MergeTree()
PARTITION BY (tenant_id, toYYYYMM(timestamp))
ORDER BY (tenant_id, timestamp)
TTL timestamp + INTERVAL 24 MONTH;

-- Monthly rollup per tenant
CREATE MATERIALIZED VIEW billing_monthly_mv
ENGINE = SummingMergeTree()
PARTITION BY toYYYYMM(month)
ORDER BY (tenant_id, month, event_type)
AS
SELECT
    tenant_id,
    toStartOfMonth(timestamp)   AS month,
    event_type,
    sum(quantity)               AS total_quantity,
    sum(cost_usd)               AS total_cost_usd
FROM billing_events
GROUP BY tenant_id, month, event_type;

-- Per-tenant daily spend (for dashboard bar chart)
CREATE MATERIALIZED VIEW billing_daily_mv
ENGINE = SummingMergeTree()
PARTITION BY toYYYYMM(day)
ORDER BY (tenant_id, day)
AS
SELECT
    tenant_id,
    toStartOfDay(timestamp) AS day,
    sum(cost_usd)           AS daily_cost_usd
FROM billing_events
GROUP BY tenant_id, day;
```

## 3. Usage Tracking Flow

```
┌──────────────────────────────────────────────────────────────────┐
│  paladin-gateway  (LLM call path)                                │
│                                                                  │
│  1. Upstream response received                                   │
│     extract: tenant_id, model, input_tokens,                    │
│              output_tokens, cached_tokens                        │
│  2. cost = (input_tokens  × input_price_per_1k  / 1000)         │
│          + (output_tokens × output_price_per_1k / 1000)         │
│          × (1 - cache_discount if cached)                        │
│  3. async goroutine → POST billing_events to ClickHouse          │
└──────────────────────────────────────────────────────────────────┘
         │ fire-and-forget
         ▼
┌──────────────────────────────────────────────────────────────────┐
│  ClickHouse  billing_events                                      │
└──────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────┐
│  MCP server  (tool call path)                                    │
│                                                                  │
│  Tool call completes → write billing_events                      │
│    event_type = 'tool_call', quantity = 1, unit = 'calls'        │
└──────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────┐
│  paladin-orchestrator  (incident path)                           │
│                                                                  │
```

## 4. Budget Enforcement

### Redis Key Structure

```
budget:{tenant_id}:{YYYY-MM}          → Float64  accumulated cost (USD)
budget_limit:{tenant_id}:{YYYY-MM}    → Float64  monthly hard cap (USD)
budget_warned:{tenant_id}:{YYYY-MM}   → 1 | nil  soft-alert already sent flag
```

### Enforcement Thresholds

| Threshold | Action                                             |
|-----------|----------------------------------------------------|
| 80%       | NATS event `billing.soft_warn` → email + dashboard |
| 100%      | Incidents still processed (P1 grace policy)        |
| 120%      | `paladin-gateway` returns HTTP 429 for LLM calls   |

### Go Middleware Sketch

```go
// BudgetMiddleware enforces monthly spend caps per tenant.
func BudgetMiddleware(rdb *redis.Client, nats *nats.Conn) gin.HandlerFunc {
    return func(c *gin.Context) {
        tenantID := c.GetString("tenant_id")
        month    := time.Now().Format("2006-01")
        capKey   := fmt.Sprintf("budget_limit:%s:%s", tenantID, month)
        accKey   := fmt.Sprintf("budget:%s:%s",       tenantID, month)
        warnKey  := fmt.Sprintf("budget_warned:%s:%s", tenantID, month)

        pipe := rdb.Pipeline()
        getAcc := pipe.Get(ctx, accKey)
        getCap := pipe.Get(ctx, capKey)
        pipe.Exec(ctx)

        accumulated, _ := getAcc.Float64()
        cap, _          := getCap.Float64()

        if cap > 0 {
            ratio := accumulated / cap
            if ratio >= 1.2 {
                c.AbortWithStatusJSON(http.StatusTooManyRequests,
                    gin.H{"error": "budget_exhausted"})
                return
            }
            if ratio >= 0.8 {
                if rdb.SetNX(ctx, warnKey, 1, 30*24*time.Hour).Val() {
                    nats.Publish("billing.soft_warn", mustMarshal(map[string]any{
                        "tenant_id": tenantID, "ratio": ratio,
                    }))
                }
            }
        }
        c.Next()
    }
}
```

Budget resets: cron job runs 00:05 UTC on the 1st of each month, deletes prior-month keys.

## 5. Invoice Generation

### Flow

```
1. Cron: 00:30 UTC on billing_day per tenant
2. Query billing_monthly_mv → aggregate by event_type
3. Apply tier discounts + add-on charges (from PG)
4. Render PDF (WeasyPrint or Stripe-hosted invoice)
5. Upload PDF → S3: invoices/{tenant_id}/{YYYY-MM}.pdf
6. Stripe: create InvoiceItem for overages → finalize invoice
7. INSERT INTO invoices (PG)
8. Send email: SendGrid template billing_invoice_v1
```

### PG Schema

```sql
CREATE TABLE invoices (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id           UUID NOT NULL REFERENCES tenants(id),
    period_start        DATE NOT NULL,
    period_end          DATE NOT NULL,
    base_amount_usd     NUMERIC(10,2) NOT NULL DEFAULT 0,
    overage_amount_usd  NUMERIC(10,2) NOT NULL DEFAULT 0,
    addons_amount_usd   NUMERIC(10,2) NOT NULL DEFAULT 0,
    total_usd           NUMERIC(10,2) GENERATED ALWAYS AS
                            (base_amount_usd + overage_amount_usd + addons_amount_usd) STORED,
    status              TEXT NOT NULL DEFAULT 'draft'
                            CHECK (status IN ('draft','open','paid','void','uncollectible')),
    stripe_invoice_id   TEXT,
    s3_url              TEXT,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_invoices_tenant_period ON invoices (tenant_id, period_start);
```


## 7. Model Price Table

```sql
CREATE TABLE model_prices (
    id                        UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    provider                  TEXT NOT NULL,
    model                     TEXT NOT NULL,
```

## 8. Free Tier Limits & Upgrade Prompts

| Usage %  | Action                                                                      |
|----------|-----------------------------------------------------------------------------|
| 80%      | In-app banner: "You've used 80% of free incidents. Upgrade to Bridge for 10×" |
| 100%     | 24h grace period: incidents processed, queued if still over after 24h       |
| > 24h OT | Incidents queued (not dropped), user notified, upgrade CTA prominent         |

P1 incidents are **never hard-blocked** regardless of billing state. Always process; flag event as `billing_review_required = true` in PG.

```sql
ALTER TABLE incidents ADD COLUMN billing_review_required BOOLEAN NOT NULL DEFAULT false;
```

Grace logic runs in `paladin-orchestrator`. Gateway budget cap (§4) applies to LLM token spend only, not incident triage decisions.
