## 3. Episodic Memory — Bi-temporal Schema

### Why Bi-temporal

| Column | Meaning | Example |
|--------|---------|---------|
| `valid_at` | When the event actually happened | Incident at 02:00 UTC |
| `recorded_at` | When the system ingested the fact | Postmortem written at 14:00 UTC +2 days |

Querying "what did the system know at time T" uses `recorded_at`.
Querying "what was true in the world at time T" uses `valid_at`.

### PostgreSQL Table

```sql
CREATE TABLE episodes (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       TEXT NOT NULL,
    session_id      TEXT,
    content         TEXT NOT NULL,
    valid_at        TIMESTAMPTZ NOT NULL,          -- when event occurred
    recorded_at     TIMESTAMPTZ NOT NULL DEFAULT now(), -- when ingested
    signature_hash  TEXT NOT NULL,                 -- SHA-256 of canonical form
    tags            TEXT[] DEFAULT '{}',
    consolidated    BOOLEAN NOT NULL DEFAULT false,
    consolidated_at TIMESTAMPTZ,
    metadata        JSONB DEFAULT '{}',
    domain          TEXT NOT NULL DEFAULT 'unknown',  -- 'infra' | 'traffic' | 'unknown' — drives decay lambda
    source          TEXT NOT NULL DEFAULT 'agent',    -- 'agent' | 'slack' | 'discord' | 'pagerduty' | 'linear' | 'postmortem'
    supersedes_id   UUID REFERENCES episodes(id)      -- for corrections
);

CREATE INDEX idx_episodes_tenant_valid
    ON episodes (tenant_id, valid_at DESC);
CREATE INDEX idx_episodes_tenant_recorded
    ON episodes (tenant_id, recorded_at DESC);
CREATE INDEX idx_episodes_sig_hash
    ON episodes (tenant_id, signature_hash)
    WHERE consolidated = false;
```

### Zep Session ID Convention

```
session_id = "incident:{incident_id}"   for incident episodes
session_id = "{tenant_id}:global"       for cross-incident search
```

### Working Memory TTL Extension (P1 Sessions)

```
P1 sessions: heartbeat-based TTL extension
  Every SetWorkingMemory call resets the TTL
  Implemented via: EXPIRE wm:{tenant}:{session}:* {ttl} after each SET
  Absolute cap: 8h (EXPIREAT = session_start + 8h, set on session create)
  P2/P3: 30min sliding TTL (no heartbeat needed — resolve fast)
```

### Zep REST Call Pattern (Go)

```go
const zepBaseURL = "https://zep.internal/api/v2"

type ZepAddEpisodesReq struct {
    Messages []ZepMessage `json:"messages"`
}

type ZepMessage struct {
    UUID      string            `json:"uuid"`
    Content   string            `json:"content"`
    CreatedAt time.Time         `json:"created_at"` // valid_at
    Metadata  map[string]any    `json:"metadata"`   // includes recorded_at
    RoleType  string            `json:"role_type"`  // "assistant"|"user"|"system"
}

func (c *ZepClient) AddEpisode(ctx context.Context, sessionID string, ep Episode) error {
    body := ZepAddEpisodesReq{
        Messages: []ZepMessage{{
            UUID:      ep.ID,
            Content:   ep.Content,
            CreatedAt: ep.ValidAt,
            Metadata:  map[string]any{"recorded_at": ep.RecordedAt, "tenant_id": ep.TenantID},
            RoleType:  "system",
        }},
    }
    url := fmt.Sprintf("%s/sessions/%s/messages", zepBaseURL, sessionID)
    return c.post(ctx, url, body)
}

func (c *ZepClient) SearchEpisodes(ctx context.Context, req ZepSearchReq) ([]ZepSearchResult, error) {
    url := fmt.Sprintf("%s/sessions/%s/search", zepBaseURL, req.SessionID)
    // POST with {"text": query, "search_type": "mmr", "limit": k}
    return c.postDecode[[]ZepSearchResult](ctx, url, req)
}
```

### Retrieval with Time-Decay Scoring

```
relevance(t) = raw_score × exp(-λ × t_days)

λ by domain:
  infra    = 0.05   (slow decay — runbooks stay relevant weeks)
  traffic  = 0.15   (moderate — patterns shift in days)
  unknown  = 0.30   (fast decay — untrusted default)

t_days = (now - valid_at).Hours() / 24
```

```go
func applyDecay(raw float32, validAt time.Time, domain string) float32 {
    lambda := map[string]float64{"infra": 0.05, "traffic": 0.15}
    λ, ok := lambda[domain]
    if !ok { λ = 0.30 }
    tDays := time.Since(validAt).Hours() / 24
    return raw * float32(math.Exp(-λ * tDays))
}
```

### Edge Types

```cypher
// Structural
(:Service)-[:DEPENDS_ON {weight: float, protocol: string}]->(:Service)
(:Service)-[:OWNED_BY]->(:Team)
(:Service)-[:HAS_SLO]->(:SLO)
(:Service)-[:EXPOSES_METRIC]->(:Metric)
(:Alert)-[:FIRES_ON]->(:Metric)

(:Deployment)-[:DEPLOYED_TO {deployed_at: datetime, deployed_by: string}]->(:Service)

// Edges get last_seen_at updated on each observation
// Edge not seen for 7 days → marked stale=true (not deleted)
// Edge not seen for 30 days → deleted (truly gone)
```

### Sample Cypher Queries

```cypher
-- Blast radius: all downstream services if `payments` degrades
MATCH (src:Service {name: 'payments', tenant_id: $tid})-[:DEPENDS_ON*1..5]->(dep:Service)
RETURN dep.name, dep.tier ORDER BY dep.tier

-- Critical path: services with no alternative route
MATCH p=(s:Service {tenant_id: $tid})-[:DEPENDS_ON*]->(t:Service)
WHERE t.name = $target
WITH p, length(p) AS depth
RETURN nodes(p) ORDER BY depth LIMIT 1

-- Topology change detection since last snapshot
MATCH (s:Service {tenant_id: $tid})-[r:DEPENDS_ON]->(d:Service)
WHERE r.updated_at > datetime($since)
RETURN s.name, d.name, r.protocol

-- Causal chain: what metric predicts alert firing
MATCH (a:Alert {name: $alert})-[:FIRES_ON]->(m:Metric)
      <-[:PREDICTS {granger_pvalue: p}]-(cause:Metric)
WHERE p < 0.05
RETURN cause.name, p ORDER BY p

-- Deployments to a service before incident (Stage 15 use)
MATCH (d:Deployment)-[:DEPLOYED_TO]->(s:Service {name: $svc, tenant_id: $tid})
WHERE d.deployed_at > datetime($incident_start) - duration({minutes: 30})
  AND d.deployed_at < datetime($incident_start)
RETURN d.sha, d.version, d.deployed_at, d.deployed_by
ORDER BY d.deployed_at DESC
```

### Go Client Sketch

```go
import "github.com/FalkorDB/falkordb-go"

type TopologyClient struct {
    db *falkordb.FalkorDB
}

func NewTopologyClient(addr string) (*TopologyClient, error) {
    db, err := falkordb.FalkorDBNew(falkordb.Configuration{
        Host: addr,
        Port: 6379,
    })
    return &TopologyClient{db: &db}, err
}

func (c *TopologyClient) BlastRadius(ctx context.Context, serviceName, tenantID string) ([]string, error) {
    graph := c.db.SelectGraph(fmt.Sprintf("topology:%s", tenantID))
    q := `MATCH (src:Service {name: $svc})-[:DEPENDS_ON*1..5]->(dep:Service)
          RETURN dep.name`
    res, err := graph.QueryWithParams(q, map[string]any{"svc": serviceName})
    if err != nil { return nil, err }
    var names []string
    for res.Next() {
        r := res.Record()
        names = append(names, r.GetByIndex(0).(string))
    }
    return names, nil
}

func (c *TopologyClient) UpsertService(ctx context.Context, svc Service, tenantID string) error {
    graph := c.db.SelectGraph(fmt.Sprintf("topology:%s", tenantID))
    q := `MERGE (s:Service {id: $id})
          SET s.name=$name, s.tier=$tier, s.tenant_id=$tid, s.updated_at=timestamp()`
    _, err := graph.QueryWithParams(q, map[string]any{
        "id": svc.ID, "name": svc.Name, "tier": svc.Tier, "tid": tenantID,
    })
    return err
}
```

## 5. Qdrant Multi-tenant Design

### Tenancy Strategy

| Strategy | When | Config |
|----------|------|--------|
| **Pool** (shared collection) | ≤ 1M vectors per tenant | payload filter `tenant_id` |

```go
func (c *QdrantClient) SearchProcedural(ctx context.Context, tenantID string, dense []float32, sparse map[uint32]float32, topK int) ([]*qdrant.ScoredPoint, error) {
    filter := &qdrant.Filter{
        Must: []*qdrant.Condition{{
            ConditionOneOf: &qdrant.Condition_Field{
                Field: &qdrant.FieldCondition{
                    Key:   "tenant_id",
                    Match: &qdrant.Match{MatchValue: &qdrant.Match_Keyword{Keyword: tenantID}},
                },
            },
        }},
    }
    // Hybrid: prefetch dense + sparse, then RRF fusion
    return c.client.Query(ctx, &qdrant.QueryPoints{
        CollectionName: "procedural",
        Prefetch: []*qdrant.PrefetchQuery{
            {Query: qdrant.NewQuery(dense), Using: proto.String("dense"), Limit: proto.Uint64(uint64(topK * 3))},
            {Query: qdrant.NewQuerySparse(sparse), Using: proto.String("sparse"), Limit: proto.Uint64(uint64(topK * 3))},
        },
        Query:  qdrant.NewQueryFusion(qdrant.Fusion_RRF),
        Filter: filter,
        Limit:  proto.Uint64(uint64(topK)),
        WithPayload: qdrant.NewWithPayload(true),
    })
}
```

### ACORN Tiered Multitenancy (Procedural)

- ACORN index enables filtered HNSW without rebuilding per tenant.
- Tenant payload field indexed as `keyword`.
- Filterable at query time; no shard per tenant needed.
- Enterprise tenants exceeding 500k procedural chunks get silo collection `procedural:{tenant_id}`.

## 6. Agentic RAG Router (Go)

```go
type MemoryPath struct {
    Backend    string   // "falkordb", "zep", "qdrant-semantic", "qdrant-proc", "valkey"
    MemoryType MemoryType
    Params     map[string]any
}

func routeMemoryQuery(q Query) []MemoryPath {
    var paths []MemoryPath

    // Multi-hop topology reasoning → FalkorDB
    if q.RequiresTopology || containsAny(q.Text, "depends on", "upstream", "blast radius", "critical path") {
        paths = append(paths, MemoryPath{
            Backend:    "falkordb",
            MemoryType: MemoryTypeSemanticGraph,
            Params:     map[string]any{"max_hops": 5},
        })
    }

    // Runbook / procedure lookup → Qdrant hybrid (ACORN)
    if q.RequiresProcedure || containsAny(q.Text, "runbook", "how to", "steps to", "playbook") {
        paths = append(paths, MemoryPath{
            Backend:    "qdrant-proc",
            MemoryType: MemoryTypeProcedural,
            Params:     map[string]any{"use_colbert": true, "self_rag": true},
        })
    }

    // Temporal / what changed → Zep bi-temporal
    if q.RequiresTemporal || containsAny(q.Text, "what changed", "before the incident", "at the time", "last week") {
        paths = append(paths, MemoryPath{
            Backend:    "zep",
            MemoryType: MemoryTypeEpisodic,
            Params:     map[string]any{"valid_at": q.TemporalAnchor, "decay_domain": q.Domain},
        })
    }

    // Semantic fact retrieval → Qdrant semantic
    if q.RequiresFacts {
        paths = append(paths, MemoryPath{
            Backend:    "qdrant-semantic",
            MemoryType: MemoryTypeSemantic,
        })
    }

    // Trivial / in-session → skip memory system, use working memory only
    if len(paths) == 0 || q.Trivial {
        paths = []MemoryPath{{Backend: "valkey", MemoryType: MemoryTypeWorking}}
    }

    // Fallback: if agent_type == "rca" and no episodic path was added, always add it
    // RCA without past incident context is flying blind
    if q.AgentType == "rca" {
        hasEpisodic := false
        for _, p := range paths {
            if p.MemoryType == MemoryTypeEpisodic { hasEpisodic = true; break }
        }
        if !hasEpisodic {
            paths = append(paths, MemoryPath{
                Backend:    "zep",
                MemoryType: MemoryTypeEpisodic,
                Params:     map[string]any{"decay_domain": q.Domain, "include_most_recent": true},
            })
        }
    }

    return paths
}
```

### Fusion After Multi-backend Retrieval

```go
func fuseResults(results [][]MemoryResult, topK int) []MemoryResult {
    // RRF: score = Σ 1/(k + rank_i), k=60
    scores := map[string]float64{}
    byID   := map[string]MemoryResult{}
    for _, list := range results {
        for rank, r := range list {
            scores[r.ID] += 1.0 / (60.0 + float64(rank+1))
            byID[r.ID] = r
        }
    }
    // sort by fused score, apply decay, return topK
    return sortAndTrim(byID, scores, topK)
}
```

## 7. Consolidation CronJob

### Algorithm (Weekly, per tenant)

```
┌──────────────────────────────────────────────────────────────────────┐
│                    CONSOLIDATION CRONJOB (weekly)                    │
└──────────────────────────────────────────────────────────────────────┘

  ┌─────────────┐
  │ Pull episodes│  SELECT * FROM episodes
  │ since last  │  WHERE tenant_id=$tid
  │ run         │    AND consolidated=false
  │             │    AND recorded_at > $last_run
  └──────┬──────┘
         │
         ▼
  ┌─────────────┐
  │ Group by    │  GROUP BY signature_hash
  │ signature   │  HAVING count(*) >= 3
  │ hash        │
  └──────┬──────┘
         │ cluster size ≥ 3
         ▼
  ┌─────────────────────────────┐
  │ LLM summarize cluster       │  claude-haiku-4-5 (cheap)
  │ → summary + provenance IDs  │  prompt: "Summarize these N episodes
  │                             │           into a single factual claim."
  └──────────────┬──────────────┘
                 │
         ┌───────┴────────┐
         │                │
         ▼                ▼
  ┌────────────┐   ┌─────────────────────────────┐
  │ Mark PG    │   │ Upsert to Qdrant semantic   │
  │ episodes   │   │ collection with:            │
  │ SET        │   │  - summary as content       │
  │  consoli-  │   │  - consolidated_from: [ids] │
  │  dated=true│   │  - source: "consolidated"   │
  │  consoli-  │   │  - BGE-M3 embedding         │
  │  dated_at= │   └─────────────────────────────┘
  │  now()     │
  └────────────┘
```

### Go Sketch

```go
type ConsolidationJob struct {
    db      *pgxpool.Pool
    qdrant  *QdrantClient
    llm     LLMClient        // internal claude haiku client
    embedder EmbedderClient  // BGE-M3 via Triton
}

func (j *ConsolidationJob) Run(ctx context.Context, tenantID string, since time.Time) error {
    clusters, err := j.fetchClusters(ctx, tenantID, since)
    if err != nil { return err }

    // Bounded goroutine pool — max 10 concurrent LLM calls
    sem := make(chan struct{}, 10)
    var wg sync.WaitGroup

    for _, cluster := range clusters {
        cluster := cluster
        wg.Add(1)
        sem <- struct{}{}
        go func() {
            defer wg.Done()
            defer func() { <-sem }()
            j.processCluster(ctx, tenantID, cluster)
        }()
    }
    wg.Wait()
    return nil
}

// LLM calls go through paladin-gateway HTTP endpoint, not direct SDK calls.
// The ConsolidationJob uses a GatewayClient that calls POST http://paladin-gateway/v1/chat
// with model alias "fast" (Tier A — haiku equivalent, cheapest).
```

## 8. Tenant Isolation Per Backend

| Backend | Isolation Mechanism | Enforcement Point | Bypass Prevention |
|---------|--------------------|--------------------|-------------------|
| Valkey 8 | Key prefix `wm:{tenant_id}:` | paladin-memory SetWorkingMemory | Key builder function; tenant_id from verified JWT claim only |
| PostgreSQL (episodes) | `tenant_id` column + RLS policy | `SET app.current_tenant = $tid` per connection | RLS enabled on table; superuser queries blocked via pg_hba; app role lacks BYPASSRLS |
| FalkorDB | Separate graph per tenant `topology:{tenant_id}` | TopologyClient.SelectGraph() | Graph name derived from verified tenant_id; no wildcard graph access |
| Qdrant Pool | Payload filter `{"key":"tenant_id","match":{...}}` | QdrantClient always injects filter | Filter injection in shared query builder; no raw query path exposed |
| Qdrant Silo | Dedicated collection `semantic:{tenant_id}` | Collection name resolved from tenant_id | Collection name allowlist checked before query |
| Zep | Session-scoped; session ownership verified | ZepClient checks session→tenant mapping in PG before call | Session ownership table with FK to tenant; no cross-tenant session access |
| Triton gRPC | Stateless; no tenant state stored | N/A | Request metadata carries tenant_id for audit only |

### PostgreSQL RLS Policy

```sql
ALTER TABLE episodes ENABLE ROW LEVEL SECURITY;

CREATE POLICY episodes_tenant_isolation ON episodes
    USING (tenant_id = current_setting('app.current_tenant'));

-- App role (never superuser)
CREATE ROLE paladin_app NOLOGIN;
GRANT SELECT, INSERT, UPDATE ON episodes TO paladin_app;
-- No BYPASSRLS privilege granted
```

## 9. Self-RAG Reflection (Procedural Retrieval)

### Scoring Rubric

| Gate | Question | Fail Action |
|------|----------|-------------|
| **IsREL** | Is this chunk relevant to the query? | Discard chunk |
| **IsSUP** | Does this chunk support a concrete answer? | If all chunks fail → no-answer |
| **IsUSE** | Is the answer useful / actionable? | Warn low confidence |

```go
    // Filter: keep only REL chunks

    for _, s := range scored {

    }

        return "", ErrNoRunbookFound  // do NOT hallucinate
```

## 11. Memory Expiry Strategies

```
MEMORY TYPE    | EXPIRY MECHANISM      | TRIGGER              | OUTCOME
Working        | TTL (Valkey)          | TTL expires          | Evicted, no archive
               | Heartbeat extension   | SetWorkingMemory()   | TTL reset, max 8h
Episodic       | Retention policy      | recorded_at > 2yr    | Archive to S3
               | Hard delete           | recorded_at > 7yr    | Deleted from S3
               | GDPR erasure          | DeleteEpisodes RPC   | Crypto-shred + soft delete
               | Correction            | New episode written  | superseded_by set, original kept
Semantic (Qdrant) | Supersession       | Source content updated | deprecated=true on old chunks
               | Quality requalification | quarterly job      | quality_score < 0.60 → removed
               | Tenant deletion       | Silo tenant deleted  | Collection dropped
Semantic (FalkorDB) | Edge staleness   | not seen 7d          | stale=true
               | Edge deletion         | not seen 30d         | DELETE edge
               | Graph deletion        | Tenant deleted       | GRAPH.DELETE topology:{tid}
Procedural     | Supersession         | Runbook updated in git | deprecated=true on old chunks
               | Source deleted        | Source deleted        | All chunks deprecated=true
               | NEVER time-based TTL  | —                    | Runbooks don't expire by time

KEY PRINCIPLE: Never hard-delete knowledge except for compliance.
               Use supersession: old chunks get deprecated=true + deprecated_at timestamp.
               "What runbook existed at time T?" remains answerable via deprecated_at filter.
               GDPR is the only case that requires actual data removal.
```

### GDPR Erasure Flow

```

Step 6: Valkey: SCAN + DEL wm:acme-corp:*

Step 7: S3: Delete all objects under s3://paladin-episodes/acme-corp/

Total time: < 5 minutes for crypto-shred (step 1), < 30 min for full erasure
GDPR 72h requirement: met with massive margin
```

## 12. Query Fanout & Prompt Assembly

Show the full pipeline from user query to assembled prompt:

```
USER QUERY: "why does payments-api keep crashing under load?"
                │
                ▼
    QUERY DECOMPOSITION (LLM Tier A, ~100ms)
    output:
      entities:   ["payments-api"]
      intent:     "root_cause_investigation"
      temporal:   "recurring"
      sub_queries:
        episodic:   "payments-api crash incidents under load"
        semantic:   "payments-api dependencies load behavior"
        procedural: "payments-api crash troubleshooting"

                │
                ▼ PARALLEL FANOUT (all goroutines fire simultaneously)

    goroutine-A: SearchMemory(EPISODIC, sub_q.episodic, include_most_recent=true)
    goroutine-B: SearchMemory(SEMANTIC, sub_q.semantic)
    goroutine-C: SearchMemory(PROCEDURAL, sub_q.procedural)
    goroutine-D: HyDE variant
                 → generate hypothetical answer (Tier A LLM)
                 → embed hypothetical answer
                 → SearchMemory(EPISODIC, hyde_embedding)
                 → union with goroutine-A results
    goroutine-E: tool calls (prometheus.query_range, loki.tail)

                │ all return
                ▼
    RRF FUSION of memory results (tool results kept separate)

                │
                ▼
    PROMPT ASSEMBLY (ordering is deliberate — primacy+recency bias):

    [1] STATIC PREFIX (cached at provider)     ~1500 tokens
        persona + constraints + output schema + tool schemas + few-shots

    [2] PROCEDURAL CONTEXT (what to do)        ≤800 tokens
        runbook chunks — FIRST because model attention highest at start
        tagged: [RUNBOOK_START]...[RUNBOOK_END]

    [3] SEMANTIC CONTEXT (what is true)        ≤400 tokens
        topology: payments-api depends on db-primary (betweenness=0.73)
        SLO: payments-api target 99.9%
        tagged: [TOPOLOGY_START]...[TOPOLOGY_END]

    [4] EPISODIC CONTEXT (what happened before) ≤360 tokens
        3 past incidents × 120 tokens each, decay-weighted
        tagged: [PAST_INCIDENTS_START]...[PAST_INCIDENTS_END]

    [5] TOOL RESULTS (what is happening now)   ≤2000 tokens
        most recent signals — LAST because model attention also high at end
        pre-computed anomaly scores included
        tagged: [TOOL_RESULTS_START]...[TOOL_RESULTS_END]

    [6] CURRENT QUERY                          ≤300 tokens
        the actual question / alert content
        tagged: [ALERT_START]...[ALERT_END] (injection resistance)
```

Why this ordering:
- Procedural first: "what to do" should be available from the model's first token of reasoning
- Tool results last: current data is most actionable — put where model pays maximum attention
- Episodes in middle: context without dominating — model uses them to inform not override current data

## 14. Memory Update Strategies

### 14.1 Runbook Auto-Update (git commit trigger)

```
GitHub/GitLab webhook fires on commit to runbooks repository
        │
        ▼
mcp-github.GetDiff(commit_sha)
        │
        ▼
DIFF SIZE ANALYSIS:
  Small diff (< 20% of file changed):
    → Targeted chunk update
    → Find chunks whose section headers match changed sections
       (header similarity > 0.90)
    → Re-embed changed chunks only
    → Mark old chunks: deprecated=true, superseded_by=new_chunk_id

  Large diff (> 20% of file changed):
    → Full re-index
    → Mark ALL old chunks: deprecated=true, deprecated_at=now()
    → Re-parse + re-chunk + re-embed entire file
    → New chunks inserted with version=commit_sha

CHUNK IDENTITY ACROSS VERSIONS:
  Match by section header similarity (cosine > 0.92):
    "Step 3: Restart the service"
    ≈ "Step 3: Restart the affected service"   → same chunk, update in place
  New section (no match in old runbook) → new chunk
  Removed section (no match in new runbook) → deprecated=true

NEVER hard-delete old chunks.
  deprecated=true chunks are excluded from normal search
  but remain queryable: "what did the runbook say at time T?"
  via filter: deprecated_at > $query_time
```

### 14.2 Topology Auto-Update (continuous)

```
Sources:
  Kubernetes events (mcp-k8s watches deployment/service events)
  OTel traces (new service→service call observed)
  CI/CD webhooks (new deployment)

FalkorDB update: always MERGE, never INSERT
  MERGE (:Service {id: $id}) SET s += $properties, s.updated_at = timestamp()
  MERGE (a)-[r:DEPENDS_ON]->(b)
  SET r.last_seen_at = timestamp()  ← updated every time edge is observed

Stale edge detection (weekly CronJob):
  MATCH ()-[r:DEPENDS_ON]->()
  WHERE r.last_seen_at < datetime() - duration({days: 7})
  SET r.stale = true

Stale edge deletion (weekly CronJob):
  MATCH ()-[r:DEPENDS_ON {stale: true}]->()
  WHERE r.last_seen_at < datetime() - duration({days: 30})
  DELETE r
```

### 14.3 Episodic Correction (wrong root cause recorded)

```
Engineer discovers recorded root cause was wrong.

WRONG approach: edit the episode in place → destroys audit trail

CORRECT approach: write correction episode

paladin-memory.WriteEpisode({
    content:      "CORRECTION: inc_20260115 root cause was NOT network
                   partition. Correct root cause: connection pool exhaustion
                   (pool_size=20, traffic spike exhausted it).",
    valid_at:     original_incident.valid_at,   ← SAME timestamp
    recorded_at:  now(),                          ← NEWER timestamp
    tags:         ["correction"],
    supersedes_id: "inc_20260115"
})

Original episode: NOT modified, NOT deleted. Kept forever.
Bi-temporal query behavior:
  "What did system know at T+2h after incident?"
    → filter recorded_at <= T+2h → returns original (possibly wrong) diagnosis
  "What is current best knowledge about this incident?"
    → no time filter, newest recorded_at wins → returns correction
  Full history of what was believed at each point: preserved
```

### 14.4 Consolidated Pattern Re-consolidation

```
Consolidated semantic pattern can become wrong as new incidents accumulate.

Pattern: "payments-api OOM → restart fixes it" (quality_score: 0.87)

New incidents arrive where restart didn't fix it:
  quality tracking in PG:
    confirmation_count: 7  (incidents where pattern was correct)
    contradiction_count: 3 (incidents where pattern failed)
    quality_score = 7 / (7 + 3) = 0.70

When quality_score drops below 0.60:
  → trigger re-consolidation of original episode cluster
  → fetch ALL episodes for this signature_hash (including contradicting ones)
  → LLM summarizes ALL episodes (via paladin-gateway, Tier A)
  → nuanced pattern emerges:
    "payments-api OOM: restart fixes in ~70% of cases.
     If caused by memory leak in recent deployment (memory growth rate > 5MB/min),
     rollback is required instead."
  → old pattern chunk: deprecated=true, deprecated_at=now()
  → new pattern chunk: version=2, active=true, quality_score reset to null

Triggered by: nightly job that checks quality_score < 0.60 per tenant
```
