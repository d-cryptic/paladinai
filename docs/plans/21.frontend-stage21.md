## 9. WebSocket Event Types

```typescript
// paladin-ws endpoint: wss://ws.paladinai.io/v2/incidents/{id}
// Auth: Bearer token in query param or Upgrade header

type AgentEvent =
  | { type: "step_start";      step: string;       timestamp: string }
  | { type: "token";           content: string;    timestamp: string }
  | { type: "tool_call";       tool_name: string;  timestamp: string }
  | { type: "tool_result";     tool_name: string;  summary: string;   duration_ms: number }
  | { type: "approval_required"; action: ProposedAction; timeout_at: string }
  | { type: "step_end";        step: string;       duration_ms: number }
  | { type: "incident_update"; incident: Partial<Incident> }
  | { type: "alert_fired";     alert: RawAlert }
  | { type: "action_status";   action_id: string;  status: ProposedAction["status"]; detail?: string }

type ApprovalCommand =
  | { type: "approve"; action_id: string; modified_params?: Record<string, unknown> }
  | { type: "reject";  action_id: string; reason: string }

// Global feed: wss://ws.paladinai.io/v2/feed  (alerts, incident list updates)
// Incident feed: wss://ws.paladinai.io/v2/incidents/{id}  (reasoning stream, approvals)

// SSE: https://api.paladinai.io/v2/incidents/{id}/timeline/stream
// → text/event-stream; each event is a TimelineEvent JSON line
```

### Client WS Hook

```typescript
// hooks/useIncidentSocket.ts
function useIncidentSocket(incidentId: string): {
  events: AgentEvent[]
  sendApproval: (cmd: ApprovalCommand) => void
  connectionState: "connecting" | "open" | "reconnecting" | "closed"
}
```

Reconnect: exponential backoff starting 1s, max 30s, jitter ±20%.
On reconnect: re-fetch snapshot from REST, then resume WS from `last_event_id`.

## 10. Performance Requirements

| Metric | Target | Strategy |
|---|---|---|
| First Contentful Paint | < 1.5s | RSC, edge deployment (Vercel) |
| First agent token rendered | < 1.5s from page load | WS connect on mount, no waterfall |
| Time to Interactive | < 2.5s | < 200KB JS, RSC offloads server logic |
| WS reconnect max gap | 30s | Exponential backoff with 30s cap |
| Dashboard revalidation | 30s | Next.js ISR (`export const revalidate = 30`) |
| Bundle size (client JS) | < 200KB | RSC + dynamic imports for charts |
| Offline stale data | Shown with banner | SWR stale-while-revalidate |

### Offline / Reconnecting Banner
