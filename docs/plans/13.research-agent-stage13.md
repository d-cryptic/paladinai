# Stage 13 — Research Agent: Weekly Crawl, Quality Filter & Knowledge Enrichment

**Date:** 2026-05-10
**Status:** Decisions locked (stage 13)
**Branch:** v2
**Scope:** External knowledge ingestion — crawl, filter, embed, and serve public incident/postmortem content to the RCA agent

---

## Overview

The Research Agent enriches PaladinAI's semantic memory layer with public incident reports,
postmortems, and engineering incident write-ups. It runs as a weekly batch pipeline, not
continuously — knowledge doesn't go stale in hours and batch is dramatically simpler.

Content is public-only, quality-filtered at two stages, and stored in a shared Qdrant
collection (`external_knowledge`). During RCA, when episodic memory returns fewer than 3
matches, the agent also queries this collection and tags results as `external_reference`.

All implementation is Go. No Python. LLM calls go through paladin-gateway. Triton is called
via gRPC from Go. Hatchet orchestrates the weekly workflow.

## 2. Crawl Sources & Methods

### 2.1 Engineering Blogs

Target sources: Cloudflare Blog, Stripe Engineering, Netflix Tech Blog, Uber Engineering,
AWS Architecture Blog, Google Cloud Blog, Fly.io, PlanetScale, Shopify Engineering.

**Fetch method:** RSS feeds first; fall back to HTML scrape if no RSS or RSS is truncated.

```go
type BlogSource struct {
    Name     string
    RSSURL   string        // primary
    ScrapeURL string       // fallback if RSS truncated
    Domain   string        // for rate limiter keying
}

var engineeringBlogs = []BlogSource{
    {Name: "cloudflare", RSSURL: "https://blog.cloudflare.com/rss/", Domain: "blog.cloudflare.com"},
    {Name: "stripe",     RSSURL: "https://stripe.com/blog/feed.rss",  Domain: "stripe.com"},
    {Name: "netflix",    RSSURL: "https://netflixtechblog.com/feed",   Domain: "netflixtechblog.com"},
    // ...
}
```

HTML scraping uses a list of CSS selectors per domain stored in config (not hardcoded).
Content is extracted as Markdown via a Go HTML-to-Markdown converter (goldmark-compatible).

### 2.2 GitHub Issues & Discussions

**Method:** GitHub GraphQL API. Search by label `postmortem`, `incident`, `outage`, or
`retrospective` across public repositories. Also search by title keywords.

```graphql
query($query: String!, $after: String) {
  search(query: $query, type: ISSUE, first: 50, after: $after) {
    nodes {
      ... on Issue {
        title body url createdAt repository { nameWithOwner }
        labels(first: 10) { nodes { name } }
      }
    }
    pageInfo { hasNextPage endCursor }
  }
}
```

Queries: `label:postmortem is:issue is:public`, `label:incident-report`, `"root cause" "timeline" label:incident`.

Rate limit: GitHub API 5000 req/hr authenticated. Use a dedicated read-only token.
Per-domain limiter: 1 req/s, burst 5.

### 2.3 Hacker News

**Method:** Algolia HN Search API (free, no auth).

```
GET https://hn.algolia.com/api/v1/search?query=postmortem+incident+outage
    &tags=story&hitsPerPage=50&numericFilters=created_at_i>UNIX_2Y_AGO
```

Queries cycled weekly: `postmortem`, `incident report`, `outage root cause`, `retrospective SRE`.
Follow `url` field to fetch the actual article. HN comments ignored (too noisy).

### 2.4 Reddit (r/sre, r/devops, r/kubernetes)

**Method:** Reddit OAuth2 API. App-only auth (client_credentials).

```
GET https://oauth.reddit.com/r/sre/search?q=postmortem+OR+incident&sort=top&t=year&limit=100
```

Store refresh token in Doppler. Rate limit: 100 req/min per OAuth token.
Fetch post body and top-level comments (≤ 3 comments, sorted by score). Ignore threads.

### 2.5 Statuspage Incidents

Public statuspage APIs for major SaaS providers (GitHub, Stripe, Vercel, PagerDuty, Cloudflare,
Datadog, Atlassian). These publish structured incident JSON with timeline and impact fields.

```
GET https://www.githubstatus.com/api/v2/incidents.json
```

Each resolved incident is a structured postmortem. Parse `incident_updates` array as timeline.

## 3. Quality Filter (Two-Stage)

### 3.1 Stage 1 — Rule-Based (No LLM)

Fast gate, runs in microseconds per document.

**Structural signals** — document must contain at least 2 of:
- `timeline` / `chronology` / timestamps (regex: `\d{2}:\d{2}` or ISO datetime density)
- `root cause` / `root_cause` / `contributing factor`
- `impact` / `affected` / `customers impacted`
- `resolution` / `fix` / `mitigation` / `remediation`
- `lessons learned` / `action items` / `follow-up`

```go
type StructuralSignal struct {
    Patterns []string // any match = signal present
}

var signals = []StructuralSignal{
    {Patterns: []string{"timeline", "chronology", `\d{2}:\d{2}`, "sequence of events"}},
    {Patterns: []string{"root cause", "root_cause", "contributing factor", "primary cause"}},
    {Patterns: []string{"impact", "affected", "customers impacted", "blast radius"}},
    {Patterns: []string{"resolution", "fix applied", "mitigation", "remediation"}},
    {Patterns: []string{"lessons learned", "action items", "follow-up", "retrospective"}},
}

func passesStructuralGate(text string) bool {
    count := 0
    for _, s := range signals {
        for _, p := range s.Patterns {
            if matchesPattern(text, p) {
                count++
                break
            }
        }
    }
    return count >= 2
}
```

**Length gate:** 200 words minimum (filters stubs), 50,000 words maximum (filters books).
Count whitespace-split tokens, not bytes.

**Date gate:** `published_date` must be within last 2 years (configurable via env
`RESEARCH_MAX_AGE_DAYS`, default 730). If date cannot be parsed, document is rejected.

**Dedup gate:** Compute `SHA-256(normalize(content))` where `normalize` lowercases,
strips HTML, collapses whitespace. Check against a Redis set `research:seen_hashes`.
TTL on set: 90 days (so we re-check if content significantly changes). Skip on collision.

### 3.2 Stage 2 — LLM Classifier

Uses a fast Tier A model (Qwen3-72B via paladin-gateway) — cheap and fast enough for batch.

**Prompt (system):** "You are a quality classifier for SRE/incident content. Score 0.0–1.0: is this a real incident postmortem with root cause analysis, timeline, and technical detail? Respond ONLY: `{\"score\": 0.85, \"reason\": \"one sentence\"}`"

**User message:** first 2000 words of content.

**Implementation:** call `qwen3-72b` via paladin-gateway, `max_tokens=64, temperature=0`.
Cache result in Redis by `SHA-256(content)` for 30 days. On cache hit, skip LLM call entirely.

**Threshold:** `score >= 0.75` to proceed. Failures logged with reason for monitoring; not retried.

## 4. Relevance Filter

Match content against a set of technology signals. Content passes if it matches at least 1
generic signal OR at least 1 stack-specific signal present in any tenant's integration list.

Since `external_knowledge` is shared across tenants, we use a broad union of all tenants'
stacks. Individual retrieval relevance is handled at query time by metadata filtering.

```go
var genericSignals = []string{
    "kubernetes", "k8s", "postgresql", "postgres", "redis",
    "nats", "prometheus", "grafana", "linux", "nginx",
    "docker", "tcp", "dns", "load balancer", "circuit breaker",
}

// Loaded from tenant config union at crawl start
var stackSpecificSignals = []string{
    "datadog", "aws aurora", "cloudflare", "pagerduty", "elasticsearch",
    "kafka", "mongodb", "mysql", "celery", "rabbitmq",
    // ... union of all tenant integration lists
}

type RelevanceResult struct {
    Score     float64  // count(matches) / total_signals_checked
    Tags      []string // matched signal names → stored as metadata
    Passes    bool
}

func filterRelevance(content string) RelevanceResult {
    matched := []string{}
    for _, sig := range genericSignals {
        if strings.Contains(strings.ToLower(content), sig) {
            matched = append(matched, sig)
        }
    }
    for _, sig := range stackSpecificSignals {
        if strings.Contains(strings.ToLower(content), sig) {
            matched = append(matched, sig)
        }
    }
    score := float64(len(matched)) / float64(len(genericSignals)+len(stackSpecificSignals))
    return RelevanceResult{
        Score:  score,
        Tags:   matched,
        Passes: len(matched) >= 1,
    }
}
```

Threshold: at least 1 match. Very broad — we'd rather retrieve and let the RCA agent
discard than miss a relevant postmortem.

The matched tags are stored as `relevance_tags[]` metadata in Qdrant, enabling future
per-tenant query-time filtering: `filter.must[].key=relevance_tags, match.any=["kubernetes"]`.

## 5. Chunking & Embedding Pipeline

### 5.1 Semantic Chunking

Postmortems have natural sections. Chunk by section boundary first, then by token count
if a section is too long (max 512 tokens per chunk for BGE-M3).

```go
var sectionHeaders = []string{
    "timeline", "chronology", "sequence of events",
    "root cause", "contributing factors",
    "impact", "blast radius",
    "resolution", "mitigation", "fix",
    "lessons learned", "action items", "follow-up",
    "detection", "recovery", "prevention",
}

func chunkDocument(doc ParsedDocument) []Chunk {
    sections := splitBySectionHeaders(doc.Content, sectionHeaders)
    chunks := []Chunk{}
    for _, section := range sections {
        if tokenCount(section.Text) <= 512 {
            chunks = append(chunks, Chunk{Section: section.Header, Text: section.Text})
        } else {
            // Split by sentence boundary, accumulate up to 512 tokens
            chunks = append(chunks, splitByTokens(section, 512, 64 /* overlap */)...)
        }
    }
    return chunks
}
```

### 5.2 Contextual Retrieval Prefix

Before embedding, prepend a context sentence to each chunk (Anthropic contextual retrieval
pattern). This dramatically improves retrieval recall for out-of-context chunks.

```go
func buildContextualChunk(chunk Chunk, doc ParsedDocument) string {
    prefix := fmt.Sprintf(
        "This is a %s about %s from %s (%s). Section: %s.\n\n",
        doc.ContentType,    // "postmortem", "incident report"
        doc.ExtractedTopic, // "Redis memory exhaustion causing 500s"
        doc.Source,         // "Cloudflare Blog"
        doc.PublishedDate.Format("Jan 2006"),
        chunk.Section,      // "Root Cause"
    )
    return prefix + chunk.Text
}
```

`ExtractedTopic` is extracted via a lightweight LLM call (≤50 tokens, Tier A model, cached)
or falls back to the document title.

### 5.3 BGE-M3 Embedding via Triton gRPC

Same embedding path as Stage 6 RAG pipeline. BGE-M3 produces dense (1024-dim) + sparse
(token weights) vectors in one call.

```go
func embedChunk(ctx context.Context, text string) (EmbeddedChunk, error) {
    resp, err := tritonClient.ModelInfer(ctx, &grpc_service.ModelInferRequest{
        ModelName: "bge-m3",
        Inputs: []*grpc_service.ModelInferRequest_InferInputTensor{
            {Name: "text", Datatype: "BYTES", Data: encodeString(text)},
        },
        Outputs: []string{"dense_embedding", "sparse_weights", "sparse_indices"},
    })
    // parse dense float32[1024] and sparse map[int]float32
    return EmbeddedChunk{Dense: dense, Sparse: sparse}, nil
}
```

### 5.4 Qdrant Upsert

Collection: `external_knowledge`. Shared across all tenants — all indexed content is public.
Upsert uses `on_conflict: overwrite`; point ID is a deterministic UUID v5 from `content_hash`
so re-crawls update metadata without creating duplicates.

Payload schema:

| Field            | Type       | Example                              |
|------------------|------------|--------------------------------------|
| `source_url`     | string     | `https://blog.cloudflare.com/...`    |
| `source_type`    | string     | `engineering_blog` / `github_issue` / `hn` / `reddit` / `statuspage` |
| `source_name`    | string     | `cloudflare`                         |
| `published_date` | ISO 8601   | `2025-11-01T00:00:00Z`               |
| `ingested_date`  | ISO 8601   | `2026-05-10T00:00:00Z`               |
| `quality_score`  | float64    | `0.87`                               |
| `relevance_tags` | []string   | `["kubernetes","redis","dns"]`       |
| `content_hash`   | string     | `sha256:abc123...`                   |
| `chunk_section`  | string     | `Root Cause`                         |
| `doc_title`      | string     | `Post-incident analysis: ...`        |
| `word_count`     | int        | `412`                                |

## 6. Hatchet Workflow (Weekly Batch)

### 6.1 Workflow Definition

`ResearchCrawlWorkflow` — Hatchet workflow, cron `0 2 * * 0` (Sunday 02:00 UTC).

```
Step            After               Timeout   Notes
─────────────── ─────────────────── ───────── ────────────────────────────────
fetch_sources   —                   2h        parallel fan-out per source type
filter_quality  fetch_sources       30m       stage1 rule-based → stage2 LLM
filter_relevance filter_quality     10m       technology signal match
chunk_embed     filter_relevance    60m        BGE-M3 via Triton gRPC
upsert_qdrant   chunk_embed         30m       external_knowledge collection
update_stats    upsert_qdrant       5m        NATS publish memory.research.stats
```

### 6.2 FetchSources — Parallel Fan-Out

`FetchSources` fans out to all source fetchers concurrently using a `sync.WaitGroup` + buffered
channel pattern. Each `Fetcher` implementation (`BlogFetcher`, `GitHubFetcher`, `HNFetcher`,
`RedditFetcher`, `StatuspageFetcher`) respects its per-domain rate limiter internally.
Fetch errors are logged and the source is skipped — partial results are acceptable.

### 6.3 UpdateStats — NATS Publish

After `upsert_qdrant` completes, publish a `CrawlStats` struct (JSON) to
`memory.research.stats`. Fields: `run_at`, `fetched`, `passed_stage1`, `passed_stage2`,
`passed_relevance`, `embedded`, `upserted`. Consumed by the monitoring dashboard.

### 6.4 Trigger

The weekly cron is configured in Hatchet. Additionally, a NATS subscriber on
`memory.consolidation.trigger` can kick off an ad-hoc crawl (used in dev/testing and
after a major incident where fresh data is needed immediately).

## 7. How Research Knowledge is Used at RCA Time

### 7.1 Retrieval Fallback

During RCA Phase 1 (broad signal gather), the agent queries episodic memory first.
If fewer than 3 results are returned with cosine ≥ 0.78, a parallel query goes to
`external_knowledge`.

```go
func (a *RCAAgent) gatherExternalContext(ctx context.Context, query string) ([]KnowledgeChunk, error) {
    results, err := qdrantClient.Query(ctx, &qdrant.QueryRequest{
        CollectionName: "external_knowledge",
        Query:          query,
        VectorName:     "dense",  // + sparse RRF fusion same as Stage 6
        ScoreThreshold: 0.72,     // looser than runbook retrieval (0.78)
        Limit:          5,
        WithPayload:    true,
    })
    if err != nil {
        return nil, err
    }

    chunks := make([]KnowledgeChunk, len(results))
    for i, r := range results {
        chunks[i] = KnowledgeChunk{
            Content:    r.Payload["chunk_text"].(string),
            SourceURL:  r.Payload["source_url"].(string),
            SourceType: "external_reference",  // tagged — agent knows this isn't tenant data
            Score:      r.Score,
            Date:       r.Payload["published_date"].(string),
        }
    }
    return chunks, nil
}
```

### 7.2 Threshold Rationale

| Collection         | Threshold | Reason                                          |
|--------------------|-----------|-------------------------------------------------|
| `runbooks`         | 0.82      | Tenant-specific, must be precise                |
| `episodic_memory`  | 0.78      | Past incidents, fairly specific                 |
| `external_knowledge` | 0.72   | Public content, less precise, broader recall OK |

### 7.3 RCA Output Citation

When the synthesis LLM uses an `external_reference` chunk, the RCA response includes:

```json
{
  "references": [
    {
      "type": "external_reference",
      "title": "Cloudflare outage on June 21, 2022",
      "url": "https://blog.cloudflare.com/cloudflare-outage-on-june-21-2022/",
      "relevance": "Similar BGP route leak caused network isolation"
    }
  ]
}
```

The system prompt instructs the LLM to cite external references differently from
internal runbooks: "Based on a public postmortem from Cloudflare (2022)..." vs
"Per your runbook RP-0042...".

## 8. Knowledge Freshness

### 8.1 Recency Decay

Each chunk's retrieval score is multiplied by a recency factor at query time.
λ = 0.001/day gives desired behavior: 2-year-old content at ~0.48×, still useful but deprioritized.

```
recency_factor = exp(-0.001 × days_since_published)

  365 days old → exp(-0.365) ≈ 0.69
  730 days old → exp(-0.730) ≈ 0.48
```

```go
func recencyFactor(publishedDate time.Time) float64 {
    daysSince := time.Since(publishedDate).Hours() / 24
    return math.Exp(-0.001 * daysSince)
}

// Applied at retrieval time by multiplying the Qdrant score
adjustedScore := qdrantScore * recencyFactor(publishedDate)
```

This is a post-retrieval adjustment. Qdrant does the initial ANN search; Go code
re-ranks by adjusted score before returning results to the agent.

### 8.2 Quarterly Re-Quality-Check

A quarterly Hatchet workflow `ResearchRequalifyWorkflow` runs every 90 days:

1. Fetch all `external_knowledge` points where `ingested_date` > 90 days ago
2. Re-run LLM classifier on cached content excerpt
3. If new `quality_score < 0.6`, delete the point from Qdrant
4. Update `quality_score` in payload for points that pass
5. Remove points where `published_date` > `RESEARCH_MAX_AGE_DAYS`

This prevents the collection from accumulating low-quality historical content.

## 9. Legal & Ethics

### 9.1 Public Content Only

Only publicly accessible content is indexed:
- No paywalled articles (Medium behind paywall, academic papers behind journal paywall)
- No private GitHub repositories (API search only returns public repos)
- No Slack archives, private forums, or internal wikis

Detection: HTTP response check — if content requires login redirect (3xx to `/login`,
`/signin`) or returns 401/403, skip and log as `access_denied`.

### 9.2 robots.txt Compliance

Fetch and cache `robots.txt` per domain at crawl start. Use `temoto/robotstxt` Go library.
User-agent: `PaladinAI-Research/1.0` with a contact URL in the `From` header.
Skip any path disallowed for our agent — log as `robots_disallowed`, do not retry.

### 9.3 PII Filtering

Before embedding, strip structured PII via regex: email addresses, phone numbers, credit card
patterns. Replace with `[REDACTED]`. IP addresses are kept (relevant to network postmortems).
Names are not stripped — too aggressive and breaks technical context (e.g., "John Allspaw").

### 9.4 Attribution

`source_url` is always stored and always cited in RCA output. The system never presents
external content as original analysis. Rate limits are set well below what would constitute
a DoS concern for any source.

## Implementation Notes

### Service Boundary

The research agent runs as a separate Go binary `paladin-research`. It shares:
- paladin-gateway client (LLM calls)
- Triton gRPC client (embeddings)
- Qdrant client (vector upsert/query)
- NATS client (stats publish, trigger subscription)

It does NOT write to paladin-memory gRPC — external knowledge goes directly to Qdrant,
not through the memory service (which manages tenant-specific episodic/procedural memory).

### Configuration

```yaml
# research-config.yaml
crawl:
  max_age_days: 730
  quality_threshold: 0.75
  relevance_min_matches: 1
  min_words: 200
  max_words: 50000

embedding:
  model: bge-m3
  max_tokens_per_chunk: 512
  chunk_overlap_tokens: 64

recency:
  lambda: 0.001   # per day decay constant

requalify:
  min_quality_score: 0.6
  interval_days: 90
```

### Monitoring

NATS subject `memory.research.stats` carries `CrawlStats` after each run.
Prometheus metrics exported:
- `research_documents_fetched_total` (counter, by source)
- `research_documents_filtered_total` (counter, by stage, result)
- `research_documents_embedded_total` (counter)
- `research_crawl_duration_seconds` (histogram)
- `research_qdrant_collection_size` (gauge)

Alerts: crawl fails to complete → PagerDuty P2. Collection size drops >10% → P2.

## Summary

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Crawl frequency | Weekly batch | Knowledge doesn't go stale hourly; simpler than continuous |
| Storage | Shared `external_knowledge` collection | All content is public; no tenant isolation needed |
| Quality gate 1 | Rule-based structural signals | Fast, no LLM cost |
| Quality gate 2 | LLM classifier ≥ 0.75 | Catches fluent-but-shallow content rule-based misses |
| Relevance filter | Union of all tenant stacks | Broad — let query-time filtering narrow per tenant |
| Retrieval threshold | Cosine ≥ 0.72 | Looser than internal docs; external content less precise |
| Recency decay | λ=0.001/day | 2yr old content at 0.48×; still useful |
| PII handling | Strip email/phone/card before embed | No PII in vector store |
| Attribution | Always cite source_url in RCA | Legal compliance + user trust |
